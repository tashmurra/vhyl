# Development

`lib` contains the library; `examples` contains complete original programs; `tests` contains fixtures and host assertions. The compiler is an external dependency. Do not add compiler crates, copied runtime code, private headers or sibling-checkout assumptions.

[compiler.json](../compiler.json) records the tested compiler repository and immutable revision. CI checks out that revision into ignored `.tools`, builds `zebc`, and uses it through its CLI. To update compatibility, change the pin and rerun source and native checks together. Library and compiler versions need not advance together.

Run the README commands. The test runner selects `--zebc`, then `ZEBC`, then PATH, without fallback after an invalid explicit selection. Native prerequisites follow the compiler's discovery settings. Tests share one temporary output/cache directory per run; no cache entry is committed. Existing output directories are refused.

Source checks cover every complete example and fixture, host protocol validation and generated catalogue consistency. Native checks use independent expected outcomes for actions, scope, travel, scheduling, actor following, dialogue and persistence. Native mode currently requires macOS because the independent inspection host uses its C toolchain. Missing prerequisites fail the requested native run.

Keep documentation with its API changes, and make examples executable in tests. Preserve code/message identity unless an intentional compatibility change is documented. Do not replace independent assertions with output snapshots generated by the same implementation.

Before a release, test a fresh source export with an empty output/cache directory, review links and the file inventory, and run a local secret scanner. Do not commit build logs, evidence, local tool fingerprints, private story data or historical planning material.

Push and pull-request CI source jobs cover Linux, Windows and macOS; routine native checks run on Apple Silicon. Manual workflow runs and published releases add Intel macOS coverage. Run the Library checks workflow manually against the relevant branch or tag when updating the compiler pin and before a release, so both macOS architectures are checked. Local Intel execution does not validate Apple Silicon, other operating systems or a minimum OS version. No CI execution is claimed solely because the workflow exists.
